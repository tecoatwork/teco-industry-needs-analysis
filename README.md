# teco-industry-needs-analysis

研究行业常规需求、常见痛点、采购触发因素与供应商选择标准，帮助B2B业务员准备更具体的客户问题与证明材料。

## 适用范围

适合行业需求研究、客户开发准备、产品规划和销售培训。它回答某类客户可能面对什么问题，不替代具体公司背调，也不自动生成市场规模结论、发送开发信或发布内容。

输入行业/产品、客户类型、目标市场和研究目的。可选提供我方产品与能力、客户访谈及业务记录。范围越具体，结论越容易验证；“美容行业”宜先按产品和买家角色拆分，而不是生成一份覆盖所有公司的痛点清单。

## 使用示例

```text
$teco-industry-needs-analysis
产品：专业脱毛蜡加热器
客户类型：美容用品品牌商与分销商，分别分析
目标市场：美国
目的：准备客户开发与需求访谈
我方资料：使用我提供的产品文件；没有证据的能力不要补写
请输出需求矩阵、重点痛点卡片和三个优先验证问题，标明来源与假设。
```

这是示例任务，不代表已经完成相关行业调查。默认中文、连续执行三阶段；也可指定仅完成一个阶段。没有我方资料仍能研究行业需求，但不能确认我方匹配度。没有联网条件时仅分析已提供材料，清楚列出未核查部分。

## 方法一 先看客户的工作与经营场景

先判断谁购买、谁使用、谁承担库存和售后，以及采购为什么发生。同一产品对品牌商可能涉及新品协作，对分销商可能涉及补货，对终端企业可能涉及操作和维护；这些只是分层方向，具体需求仍需证据。

按“客户类型—服务对象—业务目标—使用/经营场景—采购方式”建立分层表。梳理选型、评估、打样、采购、交付、使用、售后的相关环节，找出需求发生在哪里。并非每个行业都需要所有流程或角色。

## 方法二 分开四类信息

| 类型 | 定义 | 应回答的问题 |
| --- | --- | --- |
| 常规需求 | 完成工作或经营所需要的条件 | 什么必须得到满足？ |
| 痛点 | 满足这些条件时的具体困难 | 哪个环节受阻，带来什么影响？ |
| 采购触发因素 | 促使客户开始行动的事件 | 为什么现在评估或采购？ |
| 选择标准 | 比较供应商和方案的依据 | 凭什么选择，如何证明？ |

例如，“稳定补货”可以是需求；“特定场景中补货不及时”才是待证实的问题；“新渠道上线”可以形成采购时机线索；“交期与订单履约记录”可以作为评估方向。不能从其中一项直接推出其他三项。

## 方法三 从八类方向查证

1. 产品与使用表现：工作目标、规格、性能、操作体验。
2. 品质与一致性：验收、批次差异、可靠性与质量证明。
3. 成本与经营收益：采购及物流、库存、返工、维护等适用成本。
4. 供应与交付：MOQ、补货、交期、预测与连续供应。
5. 渠道与销售支持：包装、标签、展示、资料和培训。
6. 定制与开发协作：选型、样品、修改、确认、变更和上市。
7. 合作准入与风险：适用的产品、市场和买家条件。
8. 售后与持续采购：RMA、维修/换新、备件、投诉、补货和复购。

八类是检查方向，不是强制填空。设备、耗材和材料需要不同深度；无关维修或项目要求注明不适用。没有证据时报告缺口，不用行业常识补成企业事实。

## 方法四 把痛点写成可核查的卡片

每条重点痛点包含以下字段：

| 字段 | 内容 |
| --- | --- |
| 客户类型与场景 | 谁在什么工作或采购环节遇到问题 |
| 原本需求与具体困难 | 想实现什么，哪里受阻 |
| 业务影响 | 对成本、时间、使用、销售或风险的影响，未知金额不编造 |
| 当前解决方式 | 现有供应商、库存、内部流程或替代产品如何处理 |
| 剩余问题与切换障碍 | 为什么仍不理想；更换的成本、风险和条件 |
| 证据与反例 | 来源、时间、适用范围、冲突、可信度和证据状态 |
| 验证问题 | 哪个回答会改变销售判断 |
| 供应商回应与证明 | 可能有帮助的能力，以及需要出示的真实材料 |

默认展开3–5条重点痛点，证据不足时少写。重点不只由提及次数决定，还要考虑业务影响、发生场景、采购关联及当前应对是否足够。

## 方法五 判断证据能支持到哪里

先查买家采购及供应商要求、原始研究、实际业务材料，再通过行业访谈、专业资料和评论补充。官网自述、独立研究、用户评论支持的结论范围不同。引用实际读取的来源，并注明时间和研究范围。

证据状态分为重复证据支持、局部/新信号、待验证假设。多个独立材料支持某一模式，也不等于知道其行业发生率；同源转载不能算多次验证。评论缺少销量分母时不能算投诉率，售后政策不能证明实际服务质量。

详细门槛见 [证据与验证规则](references/evidence.md)。法律和市场准入事项需要核对当前官方来源和适用范围；不将买家额外要求误写成法律义务。

## 方法六 转成销售验证行动

将行业研究作为下一轮客户调查的输入：先寻找该客户是否符合场景，再提出验证问题，最后按答复准备方案。

- 确认需求：继续澄清用途、规格与采购条件，提供有依据的材料。
- 现有方案足够：确认是否存在值得变化的理由，不因发现行业痛点就强推。
- 时机未到：了解合适的联系节点。
- 明确不匹配：暂缓该方向。
- 尚未回复：保留未知，不视为需求确认或拒绝。

最多优先选择三个问题，记录为什么问、适合向哪个角色问、不同答复如何改变行动。有我方资料时匹配已证实能力；否则提供通用能力方向和待补资料清单，不承诺价格、认证、交期或效果。

### 合成教学示例

假设一份买家文件要求供应商提供备件清单：它能证明这名买家有该文件要求，不能证明行业普遍缺备件。若多个独立且相关的材料也提出相似要求，可以进一步研究该客户类型的维修支持需求，但仍不能直接断言某个目标客户正在遭遇故障。

可验证：“发生维修需求时，通常由谁储备和补充备件？”若客户确认需要供应商配合，可准备我方真实的备件和支持资料；若其现有体系已足够，则先调查有无未解决事项。这个示例不构成真实行业研究证据。

## 交付成果

报告先给行动摘要：重点客户类型、基本要求、有证据的痛点与假设、采购触发因素、下一步问题与资料。后续展示：

1. 范围与客户分层表。
2. 常规需求、触发因素和选择标准矩阵。
3. 重点痛点卡片与现有应对方式。
4. 销售切入假设和需求验证计划。
5. 来源、冲突及待补证据清单。

本Skill形成行业假设；teco-target-customer-analyse可接续验证具体公司，但不是运行依赖。不会自动调用其他Skill的发布、发送或归档流程。

## 验证与限制

结构校验和静态安全审查不证明研究结论准确、兼容所有平台或提升转化。初版未执行真实行业端到端研究；后续应使用明确产品、市场与客户类型的真实任务检验输出是否可用于访谈。
